## What
OQ-046 in `docs/OPEN_QUESTIONS.md`, decided by the user on 2026-11-25 for the recommendation: (b) keep `GIT_CONFIG_NOSYSTEM` and pass `core.autocrlf` and the credential helper through `-c` from what `git config --system` reports, when the helper names Git Credential Manager by its own path; otherwise (a), the system config read with hooks pointed at a folder that cannot exist (as built on 2026-11-08).

## Acceptance
- On Windows the app's git calls and its push get the system's `core.autocrlf` and, when it is Git Credential Manager by its own path (the `manager` helper Git for Windows ships, resolved to its executable), that helper; no other system setting reaches them while (b) applies. The fallback (a) and when it applies are as the OQ says.
- The decision is made in `internal/platform/windows` or the per-system git code (NFR-XPLAT-002), unit-tested with stand-in `git config --system` output, including a helper that names another program (refused) and a missing system config.
- `GOOS=windows CGO_ENABLED=0 go vet ./internal/... ./cmd/...` passes; issue 055 gets a line on what to check on a real Windows. OQ-046 is closed with the outcome and date.

## Notes
- 2026-11-25: built in `internal/engine/git.go`, the per-system git code beside `safeGitOn` and `gitEnvOn`, pure functions of what git printed so they are tested on any system; the engine may not import `internal/platform/windows`, and git runs through `internal/environment` (NFR-XPLAT-002, ENV-001). `systemGitOf` asks git once a run (`git config --system --includes -z --get-regexp` for `core.autocrlf` and the credential helpers; a git that did not run is asked again); `systemGitFrom` decides: (b) when every helper left after the last empty one is `manager`, `manager-core` or an absolute `C:/...` path to `git-credential-manager[-core][.exe]` with nothing after it and only escaped spaces and brackets, and none is for one address; otherwise (a), as built on 2026-11-08.
