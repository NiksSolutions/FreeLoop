## What
OQ-048 in `docs/OPEN_QUESTIONS.md`, decided by the user on 2026-11-25 for the recommendation (a): set WebKitGTK's `enable-media-stream` on each web view from `internal/platform/linux` (cgo is allowed there), and have the `.deb` recommend GStreamer's PipeWire or PulseAudio plugin.

## Acceptance
- Each Linux web view has `enable-media-stream` (and whatever WebKitGTK 4.1 needs for `getUserMedia` on the app's own scheme) turned on, and the permission request for the microphone is answered for the app's own page only, never for a framed or other page.
- `build/linux/nfpm/nfpm.yaml` recommends the GStreamer plugin(s) needed; the AppImage's GTK plugin bundling is checked for what it needs.
- It builds in the Linux image (`make linux-package` under Colima, arm64); a Go test where one can run without a display. What could not be run (a microphone on a Linux desktop) is added to issue 055. OQ-048 is closed with the outcome and date.

## Notes
- 2026-11-25: Done. `internal/platform/linux/webview_gtk3.go` (cgo, built with the gtk3 tag; `webview_nogtk3.go` is a no-op otherwise) adds a GLib emission hook on GTK's `parent-set`, so each WebKitWebView is caught as Wails v3.0.0 packs it into its window, before Wails connects its own handlers and loads the page; it sets `enable-media-stream`, keeps the address each view commits to, and answers user-media requests itself, ending the signal before Wails' handler (which allowed the microphone and the camera to any page the window showed). `mayRecord` in `webview.go` allows audio only, never video or the screen, and only for a committed page on `wails://localhost` (any port, for `make dev`). `cmd/freeloop`: a `PrepareWebViews` field in `platform.go`, set in `platform_linux.go`, called in `main.go` before the first window. Found: in the WebKitGTK 2.50.4 of Ubuntu 22.04 `enable-media-stream` is already on by default and `wails://localhost` is already a secure context (a scheme with a handler, on localhost), so no scheme is registered as secure; cross-origin frames (the preview) are refused by WebKit's permissions policy before any handler, and WebKit's request does not name the asking frame, so a frame the app gave `allow="microphone"` would be allowed (it gives none). `nfpm.yaml` now recommends `gstreamer1.0-plugins-good`, which holds GStreamer's PulseAudio source since 1.18 (`gstreamer1.0-pulseaudio` is an empty transitional package; `libwebkit2gtk-4.1-0` depends on plugins-good in Ubuntu 22.04, 24.04 and Debian 12), and suggests `gstreamer1.0-pipewire`. The AppImage: linuxdeploy's GTK plugin carries GStreamer 1.20's libraries (libgstreamer, -base, -app, -audio, -gl and others) but no plugins, and AppRun sets no `GST_*` variable, so the core loads the system's plugins from `/usr/lib/<triplet>/gstreamer-1.0` and refuses any built for a newer GStreamer (`gst_plugin_check_version`): voice input in the AppImage works on Ubuntu 22.04 and, by that source, not on Debian 12, Ubuntu 24.04 or Fedora (not tried); nothing more was bundled, which would be a decision of its own (OQ-048's note). Tests: `TestMayRecord` (no build constraint). Tried in the build image under Xvfb: a throwaway probe and the real app built with printouts, with WebKit's mock microphone: the app's page is a secure context with `navigator.mediaDevices` and `AudioWorkletNode`, gets an audio track, and the capture worklet runs; the camera, the screen, a top-level page elsewhere and cross-origin or sandboxed frames are refused; without the hook, the probe's stand-in for Wails' handler gave the microphone to the top-level http page and the camera to the app's. Without the mock and with no sound server the page gets `OverconstrainedError`, which the button reports as no microphone found. `make linux-package` (arm64, Colima) built the AppImage and the `.deb` from a clean clone. A real microphone on a Linux desktop is in issue 055.
