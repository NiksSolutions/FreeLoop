The third beta of Freeloop, with what was found and hardened after 0.1.0-beta.2: settings that are saved by one writer, a bug in forked sessions, and changes that are no longer lost when two arrive at once. *Draft: the version is still 0.1.0-beta.2 in the code; it is set when this beta is tagged.*

**Before you install.** As before, the files are not signed for Apple or Microsoft (OQ-057), so your system warns about them the first time; the checksums are signed with the project's own key (`SHA256SUMS.sig`). Check the download first:

```sh
shasum -a 256 -c SHA256SUMS --ignore-missing   # macOS
sha256sum -c SHA256SUMS --ignore-missing       # Linux, or Git Bash on Windows
```

The packages and what each system needs are as in 0.1.0-beta.1. The update check does not offer a pre-release: install this one from the Releases page over the last.

**New.**
- **A Dracula style**, listed under Built in in Settings → Appearance: Dracula's purple, cyan and pink in the dark, and its light twin Alucard in the light. Every built-in style now colours the usage charts in its own hues, at a strength where neighbouring series stay apart with any colour vision.
- **Logos in the provider marks.** A session on llama.cpp, OpenRouter or vLLM shows that project's logo where it showed two letters; their makers let other apps show them. Anthropic, OpenAI and Google ask for permission first, so their marks keep letters, but in Settings → Appearance → Provider marks **Official logo** fetches theirs from their own website when you click it, and **Picture…** takes any picture of your own; either stays on your computer.
- **Font weights.** Beside the text and code fonts in Settings → Appearance, a weight: Light, Regular, Medium or Semibold. Headings and bold text stay bolder than the text, and the terminal follows the code's.

**Fixed.**
- **A forked session's message box no longer refills itself.** Forking puts the message you forked at in the new session's box; once cleared or changed, it came back each time you opened the session again. The same held for a session continued from Needs attention and one started from the new-session form with a message. Now the box keeps what you leave in it.
- **Settings changed twice in a moment keep the second change.** The Settings page, the text size keys, the fonts and style, the sidebar's filters and every other page used to save all the settings each time, and the save that ended last won, even when it was older. Each now sends only what it changed, in the order made, and the window never goes back to an older state. This was a known gap of the second beta.
- **A settings file you edit by hand is not written over** by a change made in the app a moment later, before the app had read your edit: `config.yaml`, `providers.yaml` and `mcp.yaml`. A file broken while you type is left alone, and the app says it cannot be read.
- **Two changes at once are both kept** in the list of providers and of MCP servers: two models starred in a row, or two servers saved together, kept only one.
- **Restoring a backup** while a setting was being saved could leave the file and the app disagreeing; the restore now waits for that save.
- **A built-in style you chose takes up what a new version adds.** When an update added colours to it, the style showed as changed until you clicked Revert; now your look follows the update, unless you changed a font or a colour yourself.
- **Rewinding just as a turn ends** no longer says to stop the turn first.
- **An agent's last reply is read whole** where the app shows or uses it: a comparison's runs, a review's answer and an AFK run's review. When the app noted the git state while the agent was still writing, only the part after it was taken.
- **A quick second Y no longer answers the next request when the window was busy.** The keys wait a moment after a request becomes the one they answer, but that moment was counted from when the window got to the key, so a second press held up behind a busy moment could answer the next request. It is now counted from when the key was pressed.
- **A double click on Allow once** in a session, or a key and then a click, no longer answers twice and shows an error that the request is gone: the card's buttons wait for the answer, as they did under Needs attention.
- **Linux: the sandbox no longer refuses every command on a machine with large toolchains.** Before each command it looked through every folder a command may read, Go's module cache and Rust's toolchains among them, and gave up past 200,000 files, blaming a deny rule. It now looks only where what it protects can be. Found by reading the code; Linux has still not been run on a desktop.

**For the curious.** The engine merges each change into the settings as they are (a JSON merge patch), holding one lock from reading them to writing them, and counts the settings it holds so the window can tell an older answer from a newer one. Fuzzing and checks on random settings cover the merge.

**Known gaps in this beta.**
- The Windows and Linux builds have still not been run on a Windows or Linux desktop. Windows has no sandbox yet; use a Docker environment there.
- Push notifications have not been tried on an Android phone, and the passkey not yet on a real iPhone.
- The Anthropic provider has not been tried against Anthropic's API with a real key; only its tests check it.
- What each requirement was checked with, and what still waits for real use, is in `docs/CHECKLIST-0.1.md`.
