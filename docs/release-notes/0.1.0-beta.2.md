The second beta of Freeloop. It holds the fixes from a full review of the app (backlog issues 061 to 084), what the first testers' runs found, and a reworked release pipeline. Settings → Data → **Copy a report** still puts what an issue needs on the clipboard, and nothing is sent anywhere.

**Before you install.** As in the first beta, the files are not signed for Apple or Microsoft (OQ-057), so your system warns about them the first time; the checksums are signed with the project's own key (`SHA256SUMS.sig`). Check the download first:

```sh
shasum -a 256 -c SHA256SUMS --ignore-missing   # macOS
sha256sum -c SHA256SUMS --ignore-missing       # Linux, or Git Bash on Windows
```

The packages and what each system needs are as in 0.1.0-beta.1. The update check does not offer a pre-release: install this one from the Releases page over the first.

**What changes for you.**
- **Shell deny rules hold in more places.** A command that hides what it runs from a deny rule (a glob or a git alias in the subcommand, `env -S`, a shell reading its commands from input, `find -exec`, a wrapper such as `sudo`) now asks in a sandbox and in plan mode, and is refused in bypass mode. With `deny rm -rf *`, a plain `rm *` now asks, since a file named `-rf` would make it the denied command; `rm *.o` still runs. A deny rule on a wrapper (`sudo *`) now works. Treat shell deny rules as a guard against mistakes, as before.
- **Stop ends the commands an agent started in that turn.** Commands started in earlier turns keep running until the agent ends them.
- **A trusted project's worktree scripts wait for approval when they change**, as its hooks do. A project you trusted before this release that has a `.freeloop/worktree.yaml` asks once.
- **Approval keys never answer a plan**: a plan is approved or sent back with its own buttons, in its session. In Needs attention a held key answers once, and a second quick press does not answer the next request.
- **Rules written as `Read(./.env)`**, as Claude Code's documentation writes them, now match, imported or written by hand.
- **An external agent's request that names nothing to check asks**, and a command the app cannot read counts as hidden from your shell deny rules.
- **A new AFK run waits while the last run's branch is not merged**, since its issues are still open in your checkout and would be done again. Merge or delete that branch first.
- **Pairing a phone:** wrong codes no longer close the pairing window; each wrong code makes the next try wait longer, and Settings → Phone says how many were tried.
- **The phone asks for Face ID or Touch ID** (a passkey on the phone) before it answers a request or sends a message, at pairing and again after 18 hours. A phone paired with the first beta is asked to add its passkey; pairing it again is the safer way. Reading, Stop and notifications need no check.

**Fixed.**
- Discarding or archiving a file whose name looks like a git pattern (`src/*.bak`, `:^x`) no longer touches other files.
- An external agent's request can no longer stop the app; its terminals' output shows while a command runs, and is capped.
- A crash or a power cut leaves no session stuck in a turn, a queued task is never started twice, and a command running when the app was killed is marked as stopped.
- A rewind says which other sessions in the same folder it would reset, and waits while one of them is in a turn.
- Stop works while a turn is still taking its checkpoint; messages waiting in the queue that a stop, an archive or a quit drops are counted in the session.
- An agent that exits is started again for your next message, also when it exits just as you send it.
- A settings or rules file saved by an editor in two steps is applied only once it is whole, and a rules file with errors never drops a deny rule in force.
- A window that fell behind a burst of events catches up by itself, and sessions you only looked at no longer keep their files open.
- A changed MCP secret restarts its server; an AFK run stops if what a session left cannot be committed.
- Text you type or attach while a message is being accepted stays in the message box.
- MCP tools reach Anthropic models with their whole input schema, and two tools whose names differ only in punctuation stay apart.
- The phone: it fits a phone's screen and sends pictures; it says when the computer is out of reach instead of showing a white page; a locked phone gets its notifications; a phone counts as paired only once it has its key.
- Notifications allowed in System Settings after the app was refused take effect at once.
- Larger and smaller text work on Swiss and German keyboards (⌘+ as the keyboard types it, ⌘⇧- too), say what they did, and a shortcut can be set in Settings → Keyboard with a click.
- On Windows the window's calls to the engine are no longer refused, and the app's git keeps Git for Windows' line endings, Git Credential Manager and its TLS settings while still running no other program from the system's config (not yet seen on a Windows machine).
- Voice input works in the Linux build, and only the app's own page gets the microphone. The `.deb` recommends GStreamer's plugins; in the AppImage it works on Ubuntu 22.04, and on newer systems with a newer GStreamer it may not.

**The release itself.** You can check the project's signature with only the files you downloaded: `freeloop-sign verify -ignore-missing`; the README says how. A release now waits for every test job; it is signed in a job of its own that gets the key only for a version tag; the third-party notices name Go's own licence and every bundled package and are inside the AppImage; the Linux builds carry their commit; the AppImage's runtime is pinned by its checksum; beside each AppImage is the source of the Ubuntu libraries it carries, as the LGPL asks (`Freeloop-0.1.0-beta.2-linux-<arch>-sources.tar`, about 420 MB), and the AppImage now holds the copyright file of each of their packages; and a dependency advisory in OpenTelemetry (GO-2026-6974) is fixed.

**Known gaps in this beta.**
- The Windows and Linux builds have still not been run on a Windows or Linux desktop. Windows has no sandbox yet; use a Docker environment there.
- Push notifications have not been tried on an Android phone, and the passkey not yet on a real iPhone.
- The Anthropic provider has not been tried against Anthropic's API with a real key; only its tests check it. OpenRouter, OpenAI-compatible servers, Ollama and the external agents have been used on real accounts.
- What each requirement was checked with, and what still waits for real use, is in `docs/CHECKLIST-0.1.md`.
